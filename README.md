# Looking Glass Go: 独自RGBDプレイヤー開発レビュー資料

## 1. 開発の背景とアーキテクチャ概要

公式の `Looking Glass Studio` や `Looking Glass Bridge` が DGX SPARK (ARM64) 環境やプロキシ環境下で正常に動作しない制約を回避するため、完全にスタンドアロンで動作する軽量なRGBD動画プレイヤーを独自開発しました。

**技術スタック:**
- **Python 3.12 + PySide6**: GUIコントロールパネル
- **OpenGL (PyOpenGL) + GLFW**: ハードウェアアクセラレーションによるリアルタイム描画
- **GLSL Fragment Shader**: RGBD形式（Side-by-Side）からの Backward Warping（後方ワープ）と、Lenticular Interleaving（レンチキュラー合成）をGPU上でリアルタイム実行
- **シェルスクリプト**: マルチモニターの自動配置と複数インスタンスの同期再生制御

## 2. 「ノイズ（モアレ）」問題の根本原因

開発中、`Depthiness`（立体感の強さ）を上げると映像全体に激しい縦縞のノイズが発生する問題に直面しました。

> [!WARNING]
> これは映像処理上のランダムノイズではなく、**「ソフトウェア側が想定するレンズのピッチ（間隔）」と「ハードウェアの物理的なレンズのピッチ」のズレによって生じる「モアレ（干渉縞）」**です。

### 光学的なメカニズム
Looking Glass Go の表面には、斜めに配置された無数のレンチキュラーレンズ（かまぼこ型のレンズ）が貼られています。
シェーダープログラムは、画面上の各ピクセルが**「どのレンズの、どの角度（View）から見えるべきか」**を計算し、視差（パララックス）を生成します。

- 物理レンズと計算値が**完全に一致**している場合：
  レンズが視差の境界線を綺麗に隠し、人間の目には滑らかな立体映像（1つのView）として見えます。
- 計算値（PitchやSlope）が**わずかでも（0.01でも）ズレている**場合：
  レンズと描画ピクセルの位相が定期的にズレてしまい、本来見えないはずの「別の角度用のピクセル」が網目状に見えてしまいます。これが激しいノイズの正体です。

## 3. パラメータの最適値と、現状の課題

公式の Looking Glass Studio では、この問題を回避するために**「デバイス本体のEEPROMに工場出荷時に書き込まれた固有のキャリブレーション値」**をUSB経由で直接読み取っています。

現在我々のシステムでも `lkg_read_calibration.py` を用いてUSB HIDからの読み取りを実装していますが、環境依存（`hidapi` ライブラリの不足やプロキシエラー）により読み取りに失敗し、以下の**「安全なデフォルト値」**にフォールバックしています。

- **Pitch (レンズ幅)**: `49.82` または `47.5` 付近
- **Slope (レンズの傾き)**: `-5.48` または `-5.5`
- **Center**: `0.157` または `0.0`

> [!IMPORTANT]
> この値はあくまで「平均的な値」であり、接続されている**個別のLKG Goハードウェアにとっては不正確**であるため、Depthinessを上げるとモアレが発生してしまいます。

## 4. 今後の精度向上・解決アルゴリズム（Looking Glass Studio代替策）

公式ツールが使えない環境で、公式と同等の立体品質を得るためには、以下の2パターンのアプローチでキャリブレーション精度を向上させる必要があります。

### アプローチA: USB HID通信の環境依存解消（システム的解決）
仮想環境（`lkg-env`）内でUSBデバイスへ直接アクセスできるよう、ネイティブライブラリの整備を行います。
1. `hidapi` および `pyusb` の依存関係をオフライン環境またはプロキシをバイパスしてインストール。
2. udevルール（LinuxのUSB権限）を設定し、root権限なしでVID: `05df`, PID: `16c0` (Looking Glass Go) の Feature Report `0x00` を読み取れるようにする。

### アプローチB: 視覚的スイートスポット探索GUIの実装（アルゴリズム的解決）
万が一USBからの読み取りが不可能な場合に備え、人間の視覚を利用して最適なPitchを逆算する機能です。（今回実装した `lkg_control_panel.py` がそのプロトタイプになります）

1. **テストパターンの表示**: 
   細かい白黒ストライプ、またはDepth値が最大（Z-indexが高い）のフラットな画像を専用描画します。
2. **ピッチスイープ（Pitch Sweep）**: 
   Pitchの値を `47.00` から `50.00` の間で `0.05` 刻みでスライダー移動させます。
3. **位相の一致点の特定**: 
   モアレ（干渉縞）の幅は、正解のPitchに近づくにつれて太くなり、**完全に一致した瞬間にモアレが消失**（画面全体が一色にベタ塗りされる、またはクリアな映像になる）します。
4. その時の値を真のPitchとして `lkg_calibration.json` に永続保存します。

### 結論とネクストアクション
現在の「GUIからPitchを0.05刻みで操作できるコントロールパネル」を用いて、まずは開発チーム内で**「モアレが消失するスイートスポット」**を目視で見つける運用テストを行ってください。
スイートスポットが見つかれば、Depthinessを `1.0` などの強い値に設定しても、ノイズのない完全な3Dホログラムとして表示されることが確認できます。
